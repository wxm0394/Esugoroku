## 4. Known Pre-Issues (Pre-Fix Baseline)

| Issue | Location | Impact |
|---|---|---|
| Manifest `path` fields use relative paths instead of browser-accessible `/assets/...` URLs | `assets/manifest/asset-manifest.json` | Browser fetches fail due to incorrect URL resolution |
| `server.js` static route mapping for `/assets/*` and `/assets/aistudio/*` needs verification | `server.js` | Asset serving from browser may not resolve correctly |
| `BrowserAssetAdapter` not wired as default adapter in `AssetManager` | `assets/asset-manager.js` | Asset loading falls back to non-browser-optimized paths |
| `pendingLoads` de-duplication not implemented in `AssetManager` | `assets/asset-manager.js` | Concurrent image loads create duplicate promises |
| `playSound()` first-play AudioContext cache bug | `mobile/js/audio.js` | First sound play fails due to unlocked AudioContext |
| `getAssetsByGroup()` does not merge `groupDef.assets`, `asset.group`, or ID prefix matches | `assets/manifest/asset-registry.js` | Group queries miss assets registered under alternative keys |
| Master Sheets loading bypasses `AssetManager` in some code paths | `mobile/js/nishikie_woodblock.js` | Inconsistent asset resolution; fallback to Base64 silent images |
| Ajv JSON Schema validator not fully integrated into `tools/validate_assets.mjs` | `tools/validate_assets.mjs` | Schema validation cannot be executed via `npm run assets:validate` |
| No HTTP asset check tool exists | `tools/` | Inability to verify browser-accessible asset URLs |
| No AssetManager unit test exists | `tools/` | No automated test coverage for AssetManager core methods |
