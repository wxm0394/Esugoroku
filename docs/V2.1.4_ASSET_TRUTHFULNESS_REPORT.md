# Esugoroku V2.1.4 Asset Truthfulness & Runtime Integration Engineering Report

## Executive Summary

Esugoroku V2.1.4 fixes systemic asset verification loopholes and runtime asset cache decoupling across the codebase. Prior versions allowed fuzzy prefix matching in static validation, relied on flawed HTTP checks that passed HTTP 404 responses as non-errors, improperly classified synthetic/programmatic 3D models and WebAudio buffers as physical disk files, and operated duplicate asset caches across `nishikie_woodblock.js` and `prints.js`.

This release enforces **Asset Truthfulness**:
1. Static disk validation (`tools/validate_assets.mjs`) strictly verifies exact paths without prefix matching.
2. The HTTP verification tool (`tools/test_assets_http.mjs`) starts an in-process HTTP server on a random port, performs live GET requests, distinguishes physical vs. programmatic assets, and fails on any physical asset HTTP 404.
3. Programmatic assets (3D pawn, bone dice, SFX roll/clack, 4 BGM themes) are re-classified in `asset-manifest.json` (`sourceType: "factory"`, `type: "programmatic"`) and supported by a Programmatic Factory Registry in `AssetRegistry`.
4. Runtime modules (`nishikie_woodblock.js` & `prints.js`) delegate 100% of asset preloading, retrieval, and caching to the single-instance `AssetManager`.
5. `AssetManager` and `BrowserAssetAdapter` were fixed for synchronous `pendingLoads` de-duplication, safe protocol URL joining without scheme corruption, WebAudio `AudioContext` lifecycle management, and SVG fallback handling.
6. Git tracking was cleaned up by ignoring and untracking `node_modules/`.

---

## Technical Details & Changes

### 1. Problem A: Exact Path Verification in `tools/validate_assets.mjs`
- **Root Cause**: `validate_assets.mjs` contained a fallback loop using `fs.readdirSync()` to prefix-match file paths when an exact match failed. For example, `font.shippori-mincho` (`shippori-mincho.woff2`) matched `shipporiminchob1_001_...woff2` via fuzzy prefix matching.
- **Fix**: Removed the fuzzy prefix-matching loop from `validate_assets.mjs`. Updated `asset-manifest.json` to specify the exact font path on disk: `/assets/fonts/shipporiminchob1_001_wXK1E2wCr44tulPdnn-xbIpJ9RgT9-nKLoxP2xCx5m9m2kVb449GP2pukmm_jQafeeM.0.woff2`.

### 2. Problem B: Standalone HTTP Endpoint Checker (`tools/test_assets_http.mjs`)
- **Root Cause**: The previous HTTP validator used external `python -m http.server` on port 3000 and silently passed HTTP 404 responses for missing assets.
- **Fix**: Redesigned `tools/test_assets_http.mjs` to:
  - Dynamically find an available port via Node's `net` module and create an in-process HTTP server using `http.createServer`.
  - Perform real HTTP `GET` requests against all registered asset URLs.
  - Correctly identify physical vs. programmatic/factory assets (`sourceType: "factory"`, `type: "programmatic"`, or data URIs).
  - Report HTTP 200 for physical assets (84 items) and fail execution (Exit code 1) on any physical asset 404.

### 3. Phase 1: Programmatic Resource Re-classification & Factory Registry
- **Schema & Manifest Update**: Extended `assets/manifest/asset-schema.json` to include `sourceType` with enum `["physical", "factory", "procedural"]`. Reclassified 8 programmatic assets (`piece.kokeshi`, `model.dice.bone`, `audio.sfx.dice-roll`, `audio.sfx.wood-clack`, `audio.bgm.tokaido`, `audio.bgm.yokai`, `audio.bgm.kesshu`, `audio.bgm.genji`) with `type: "programmatic"` and `sourceType: "factory"`.
- **Factory Registry Implementation**: Added `programmaticRegistry` Map, `registerProgrammaticAsset()`, `isProgrammatic()`, `getProgrammaticAsset()`, and `createProgrammaticAsset()` in `assets/manifest/asset-registry.js`. Registered default fallback object generators for 3D kokeshi, dice, SFX, and BGM.

### 4. Phase 2: Master Sheets Integration (`mobile/js/nishikie_woodblock.js`)
- **Fix**: Updated `preloadUkiyoeSheets()` to preload master sheet assets via `AssetManager.preloadAsset(assetId)` and populate `loadedImages.set(key, image)` from `AssetManager` cache/loads. Guaranteed that `getSheetImage(key)` returns valid `HTMLImageElement` instances.

### 5. Phase 3: Print Assets Unification (`mobile/js/prints.js`)
- **Fix**: Refactored `mobile/js/prints.js` to eliminate local image caching maps. All print accessors (`getPrint()`, `getPrintURL()`, `loadAllPrints()`, `isPrintLoaded()`) delegate directly to `AssetManager.loadedImages` and `AssetManager.preloadAsset()`.

### 6. Phase 4: AssetManager & BrowserAssetAdapter Enhancements
- **Pending Loads Timing**: `this.pendingLoads.set(id, loadPromise)` is set synchronously before async work, preventing race conditions when duplicate preload calls occur in rapid succession. `finally { this.pendingLoads.delete(id); }` guarantees cleanup upon resolution or rejection.
- **URL Protocol Preservation**: Refactored `BrowserAssetAdapter.toLoadUrl()` using regex `/^(data:|blob:|https?:\/\/|\/\/)/i` and safe string concatenation (`${base}/${path}`) to avoid regex-replacing protocol slashes (`http://` -> `http:/`).
- **Programmatic Preloading**: `AssetManager.preloadAsset()` automatically delegates programmatic assets to `registry.createProgrammaticAsset()` and caches the result in `assetCache`.
- **AudioContext & Fallbacks**: Ensured lazy initialization and suspended state resumption for WebAudio `AudioContext`. Gracefully catch loading errors and fall back to SVG data URIs.

### 7. Phase 5: Git Cleanup
- **Fix**: Added `node_modules/` and `/package-lock.json` to `.gitignore`. Executed `git rm -r --cached node_modules/` to untrack node modules from git history.

### 8. Phase 6: Regression Testing Suite
- **Results**:
  - `node tools/validate_assets.mjs`: 84 verified physical assets, 8 missing/programmatic warnings, 0 errors.
  - `node tools/test_assets_http.mjs`: 84 HTTP 200 OK, 8 programmatic skipped, 0 failed endpoints.
  - `node tools/test_asset_manager.mjs`: 5 test suites passed (AssetRegistry, AssetManager URL, Request De-duplication, Programmatic Preloading, BrowserAssetAdapter URL joining).
