# Esugoroku V2.1.4.1 — Factory Integrity & Runtime Binding Report

## Overview

This report documents the implementation of **Esugoroku V2.1.4.1**, focusing on factory integrity, runtime binding, and programmatic asset resolution. The changes ensure that programmatic assets (3D models, audio themes, SFX) are properly registered, resolved, and cached without relying on non-existent file paths.

## Changes Summary

### Phase 1 & 2: Programmatic Factory Registry & Asset Mapping

- **File**: `assets/manifest/asset-registry.js`
- **Change**: Implemented `AssetRegistryImpl` with full factory registration support:
  - `registerProgrammaticAsset(id, resolver)` — registers runtime resolvers
  - `resolveProgrammaticAsset(id)` — resolves/create programmatic asset instances
  - `createProgrammaticAsset(id)` — alias for `resolveProgrammaticAsset` (AssetManager compatibility)
  - `isProgrammatic(id)` — checks if asset is programmatic type
  - `getProgrammaticAsset(id)` — gets programmatic asset definition

- **8 Programmatic Assets Mapped**:
  - `piece.kokeshi` — 3D kokeshi pawn factory (`createKokeshiPawn`)
  - `model.dice.bone` — 3D bone dice factory (`createBoneDice`)
  - `audio.sfx.dice-roll` — WebAudio dice roll SFX (`audio.throwDie`)
  - `audio.sfx.wood-clack` — WebAudio wood clack SFX (`audio.woodClack`)
  - `audio.bgm.tokaido` — BGM theme (tokaido)
  - `audio.bgm.yokai` — BGM theme (yokai)
  - `audio.bgm.kesshu` — BGM theme (kesshu)
  - `audio.bgm.genji` — BGM theme (genji)

### Phase 3: Manifest & Schema Update

- **File**: `assets/manifest/asset-manifest.json`
- **Change**: Removed non-existent paths (`.glb`, `.ogg`, `.mp3`) for programmatic assets and added `implementationKey` field to all 8 programmatic assets.

- **File**: `assets/manifest/asset-schema.json`
- **Change**: Added JSON Schema Draft-07 `if/then/else` conditional constraints:
  - `if` asset type is `programmatic` → `implementationKey` is required
  - `else` (non-programmatic) → `path` is required

- **File**: `tools/validate_assets.mjs`
- **Change**: Updated audit loop to treat `type: 'programmatic'` as valid without physical path requirement.

## Key Technical Decisions

1. **Method Name Alignment**: `AssetRegistryImpl` defines `resolveProgrammaticAsset(id)` while `AssetManager` checks `typeof this.registry.createProgrammaticAsset === 'function'`. Added `createProgrammaticAsset(id)` as a delegating alias to resolve the naming mismatch.

2. **Promise-based Concurrency**: `AssetManager.pendingLoads` Map ensures that concurrent `preloadAsset()` calls for the same programmatic asset share a single factory execution, preventing duplicate Three.js/WebAudio initialization overhead.

3. **Schema Conditional Validation**: JSON Schema Draft-07 `if/then/else` cleanly separates physical asset rules (`required: ["path"]`) from programmatic factory rules (`required: ["implementationKey"]`), eliminating the need for path exemptions in HTTP checks.

4. **Resolver Registration**: `registerProgrammaticAsset(id, resolver)` now also populates `programmaticRegistry` if not already present, enabling the test mock pattern of `registry.registerProgrammaticAsset(...)` + `registry.assetsMap.set(...)`.
